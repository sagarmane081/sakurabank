## Known limitation: direct deposits and the ledger
`Account.deposit()` currently updates the account's balance directly and
does not create ledger entries — only transfers (via `TransferService`) do.
This means the reconciliation job's `SUM(debits) == SUM(credits)` check is
correct for all transfer activity, but does not yet cover the "how did money
enter the system" side.

**Correct fix**: introduce a system "external clearing" account; deposits
become a transfer from that account, giving every balance change a ledger
trail. Not implemented under this deadline — documented here so it's a known
decision, not a blind spot.

## Known limitation: API layer test coverage
`AccountController` (opened tonight, July 30–31) does not yet have a
dedicated controller test — TransferController does. The JaCoCo gate
protects the service layer specifically; see current coverage report
in CI artifacts. Adding AccountControllerTest is the first item for
the next work session.
